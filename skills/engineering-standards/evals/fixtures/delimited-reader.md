# Delimited record reader

The public `readRows(input, { delimiter })` API promises to return all fields,
including empty ones. Calling it with `"sku,\n"` yields one field instead of
two. Files generated by this repository's writer always end each row with a
nonempty field. A legacy import adapter uses `readRows` and needs the complete
rows. A proposed patch exports the private row decoder for the adapter to call.

A second report comes from a harness that mutates the reader's private
delimiter field between rows. The reader then misreads the next record. Public
callers supply the delimiter when opening the reader. No supported operation
for changing it midstream is documented.
